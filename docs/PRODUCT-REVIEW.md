# 0.1.5 产品审查与改进建议

本次以当前源代码、现有实现矩阵和真实 Electron 窗口为依据。结论：选人阶段的核心链路已经接入，但还不能宣称“完整对齐 WeGame”。下一步应优先确认 Windows 客户端联动和数据可靠性，再增加辅助模块。

## 本轮已改进

| 发现的问题 | 0.1.5 的处理 |
| --- | --- |
| 对位详情和热门榜排在推荐前面，窄侧栏里难以快速找到方案 | 缩小英雄与自动配置区，简化分路条；开局页默认收起对位详情，热门榜移到方案之后。430×900 实际窗口首屏可见一张完整卡片及下一张卡片 |
| 未连接客户端仍显示 AUTO“已就位”，容易误判为可以写入 | 根据连接、阶段、锁定、英雄/模式匹配、加载及恢复状态显示准确提示；仅可配置时启用主按钮 |
| 卡片“已选用”容易与“已经配置进客户端”混淆 | 改为“已选择”，只表示方案偏好；写入结果保留独立反馈。错误反馈持续显示至手动关闭 |
| 选人时浏览其他英雄后，缺少快速返回入口 | 出现本局提示和“回到本局”，异英雄/模式的方案禁用写入 |
| 战报离开结算或切页就消失 | 在同次运行中保留到下一次选人；大厅/匹配只读，离开结算立即收起点赞。断连或新选人清除旧报告 |
| 新选人可能停留在上一局页面 | 进入新选人自动回到推荐页，并重置赛后页面触发标记 |
| 游戏中隐藏后缺少明确的后台入口 | 新增 Windows 托盘：双击显示，右键显示/隐藏/退出；关闭按钮在托盘可用时隐藏到后台，手动隐藏不被吸附轮询立即唤回 |
| 对位正文、来源和玩家名过小，榜单空结果不够明确 | 提高关键文字字号/对比度；分路榜增加无结果与重试反馈；保留深紫、荧光绿、粉色及游戏贴纸风格 |

## 建议优先级

| 优先级 | 尚需完善 | 原因与建议验收标准 |
| --- | --- | --- |
| P0 | Windows 真实客户端验收 | 当前主机为 macOS。先验收安装、锁定/交易/重随后的自动配置、完整符文/装备/技能写入、失败补偿、账号切换、荣誉投票及托盘；再测 100%/125%/150% 缩放与双屏。检查表见 [WINDOWS-ACCEPTANCE.md](WINDOWS-ACCEPTANCE.md) |
| P1 | 带版本和时间的磁盘推荐缓存 | 推荐目前主要是短时内存缓存，重启或网络不稳定时缺少历史方案。建议按英雄/分路/模式/统计版本保存最近成功数据；失败时展示缓存和时间，明确过期状态，过期或不匹配版本继续禁止写入。与仅缓存英雄资源区分 |
| P1 | 场景化方案与差异说明 | 当前有真实多方案和胜率排序，但缺少“打消耗/防爆发/对坦克”等可解释标签。建议先基于可信装备属性和可验证的来源标记差异，按对手伤害/控制类型提供参考；没有数据不生成“克制胜率” |
| P1 | 更具体的英雄对位攻略 | 当前是双方基础技巧、分路提醒和对阵整场胜率，尚不是逐英雄配对的战术库。建议维护带版本/来源的配对说明，先覆盖热门对位，解释关键技能、换血时机和成装调整；分路推测继续允许纠正 |
| P1 | 推荐统计质量更直观 | 当前说明了核心装/符文样本含义和统计范围。可继续补低样本提示、更新时间、国服与统计版本差异，以及当前偏好相对最高胜率方案的差别；保持用户要求的胜率降序，不把偏好置顶 |
| P2 | 可编辑/收藏的个人方案 | 当前能记住来源方案偏好，但不能创建个人符文/装备组合。建议增加收藏、复制后编辑、导入导出；保存及应用都经过现有合法性校验，版本更新时提示失效项 |
| P2 | 更有依据的赛后分析 | 当前展示事实指标与基础复盘提示，没有分路/时长/段位基准。可在有相同统计口径时补分时资源、对位差异和可操作的复盘入口；缺数据时不编造评分或失败原因 |
| P2 | 长期运行与更新维护 | 在真实 Windows 对局记录 CPU/内存、后台请求量、FPS/延迟；补接口失效诊断和版本发布说明。当前尚无可声称通过的性能结论，也没有自动更新分发服务 |

建议迭代顺序：先完成 P0 的一轮自定义对局验收，再做磁盘缓存与方案差异说明，最后扩展热门对位攻略和个人方案。主链路稳定后再决定是否引入新的常驻模块。

## 需求中仍未交付或需调整的内容

- **阵容总胜率与线杀率**：当前只有英雄对阵的整场胜率。需要独立数据和模型，不能平均五个英雄的胜率当作队伍获胜概率。
- **游戏内计时、视野和实时提醒**：尚无可靠输入。用户后来要求开局隐藏，因此默认不新增游戏内悬浮窗；若后续提供，应明确可用数据、手动开关和展示时机。
- **死亡即时回放**：现在是战绩中的整场回放入口，不是阵亡前后视频；需要单独评估录制、性能与存储。
- **海克斯与斗魂数据深度**：海克斯已独立识别，但装备暂参考普通大乱斗并明确标注；不展示该模式独立胜率或常规符文。斗魂只有识别，尚无阶段、血量或胜负展示。云顶已有阵容方案查看。
- **队友侦查、自动接受和自动 BP**：尚未纳入。侦查不能绕过匿名身份限制；自动化优先级低于配置可靠性。若以后加入，应明确支持的客户端范围和用户开关。
- **“每英雄每常用模式至少 2—3 套”**：真实来源样本不足时当前可能少于三套，需要额外可信数据源或经过维护的备选攻略，不能复制改名补数。

PRD 关于 WeGame 准确率、当前功能可用性的描述未独立核实，不能用其具体数字验收本项目。功能覆盖以 [实现矩阵](IMPLEMENTATION.md) 为准。

## 本轮验证及限制

- TypeScript 类型检查、生产构建通过；126 项自动化测试通过，新增配置状态和战报保留阶段覆盖。
- 实际 Electron 窗口检查真实五套推荐、430×900 信息层级；隔离结算样例检查切页保留、返回大厅只读、新选人清除及最小窗口。样例未向任何真实账号投票。
- 界面检测器的两项单侧边框提示已审阅：历史战绩的胜负色条和本局浏览提醒保留，属于当前游戏界面的语义提示，没有因此扩大重设计范围。
- Windows 托盘、LCU 写入、窗口吸附、结算投票和游戏性能尚未实机验收；安装包生成也不等同于上述行为验证通过。

托盘实现另参考了 [Electron Tray 官方文档](https://www.electronjs.org/docs/latest/api/tray) 和 [应用退出事件](https://www.electronjs.org/docs/latest/api/app#event-before-quit)，经 GitHub 原始文档核对。现有统计和 LCU 来源见实现矩阵末尾。
