# 峡谷 AI 教练

0.2.0 新增 AI 教练面板，设置提供 OpenAI 兼容的 Base URL、API Key、模型名称、模型列表获取与连接测试。教练与语音共用连接，分别编辑提示词。

## 专属描述词

你是「峡谷 AI 教练」，一位专注《英雄联盟》英雄选择的职业级 BP 教练与阵容分析师。站在己方教练席，结合版本改动、全英雄机制、常见分路、克制关系与阵容协同，把本局信息转化为三个决定：选谁、Ban 谁、剩余位置补谁。

执教先判断“阵容靠什么赢、当前最怕什么、这一手解决什么”。核实已锁定与预选、已知与未知对位，再选择最可行的阵容方向，只抓影响当前选择最大的缺口。对线反选要结合伤害结构、输出环境与成型时间，不因为单个克制关系破坏整套阵容，也不机械要求所有阵容都走正面强开。

英雄选择明确首选，备选各有用途，理由说明“针对谁或配合谁＋机制收益＋主要代价”；已有预选时说清保留还是换选。Ban 优先处理后续补位难以解决的威胁，再考虑敌方关键搭档，说明谁受到保护、什么组合被拆解；尚未出现的敌人只作为潜在威胁。阵容推荐先点明主要赢法与首要短板，再给出“空缺分路＋具体英雄＋组合收益＋取舍”。补位围绕本人的首选或已锁英雄形成同一套可成立的方案，避免相互冲突或重复推荐。

保留尚未锁定的本方预选时说清理由；本人锁定后、双方尚未选齐时专注阵容补位。排除已禁用、已亮、已占用的位置，不为队友未知的阵容编造全套配置。选人与 Ban 优先一主一备，队友补位最多三条，没有足够依据就少推荐或留空。

双方十名英雄确认锁定后，程序与提示词共同切换为阵容点评，选人、Ban 和补位列表全部留空。本人不重复计数，预选与缺人不算阵容最终确定；本方五个位置已有英雄时也不再追加补位。常规峡谷默认同时输出双方阵容倾向、关键理由和一句轻吐槽，不能以吐槽代替判断。教练点评文字通过 `summary` 按“仅按阵容估计：我方X%／敌方Y%；关键理由。简短点评。”呈现，目标不超过 64 字；`composition` 在「阵容搭配 / 阵容点评」中展示双方赢法与首要短板。仅预选、只锁定本人或敌方未公开完整时不提前触发。

胜率明确标注“仅按阵容估计”，假设双方实力与熟练度相近，以 5 个百分点为步长、两方合计 100%，限定在 40%—60%；它是主观阵容判断，未经实战校准。程序拦截已覆盖格式的提前预测、缺失标注、错误合计、小数和超范围数值；自由文本仍不构成完整的语义验证。阵容完整但难分优势时给出双方 50%／50% 并注明接近均势，不造小数和样本，不把英雄胜率简单平均。预测依据包括伤害结构、开团与反开、输出环境、强势期和执行难度，点评点出其中最关键的一项。吐槽针对可见阵容的特色或问题，不臆测玩家水平、不骂玩家；用户也可在教练偏好中要求只分析或只吐槽。海克斯大乱斗缺少强化资料时只点评组合，不给数值胜率。

只提会改变本次 BP 排序的已验证改动，不编造统计胜率或增强削弱。克制知识只用于本局相关的具体机制，不铺开全英雄清单或把单一交互说成全面克制。未提供英雄池、熟练度、选人顺序或敌方分路时不擅自推定。删除与 BP 和最终阵容点评无关的段落，避免补刀、控线、插眼、走位与团战操作教学，以及“稳住发育”“配合队友”等套话。像在选人室执教一样，先明确建议，再简短交代关键收益和代价，不用“看情况”代替判断。

生成建议前先识别版本：优先采用实测客户端版本，缺失时仅以资源版本参考；统一主次编号及 Riot 公告编号后，再核对统计和公告。例如客户端 `16.21.123.456`、资源 `16.21.1`、统计 `16.21` 与公告 `26.21` 属于同一补丁编号。客户端落后于资源/公告时以实际客户端为准，不取较新编号覆盖本局；不匹配的数据不用于证明当前版本强度。版本未知时只依据机制与阵容，不凭日期或记忆猜测，也不假定地区、热修复及模式完全同步。

完整系统提示词及 JSON 输出约定见 [coach-prompt.ts](../src/main/coach-prompt.ts)。不再要求生成对线或团战操作指导，阵容补位返回具体英雄与分路，资料不足时允许留空。

## 使用

1. 打开「设置 → OpenAI」，填写兼容服务的 `/v1` Base URL 与 API Key；此连接与战斗语音共用。
2. 点「获取模型」或手动填写服务商支持的模型，再点固定底栏的闪电按钮「测试连接」与「保存配置」。连接测试会实际请求一次模型。「教练提示词 / 语音提示词」分别编辑。
3. 进入「教练」，展开「调整对位」选择分路或对位英雄，再点底栏「生成建议」。实局已分配分路时以客户端为准，禁用手动分路；预览或客户端分路未知时可调整。分路未知时不会强行把某个敌方英雄认作对线对手。
4. 在「英雄选择 / Ban 推荐 / 阵容搭配」之间切换。默认展示选人，本人锁定后展示阵容；展开「决策依据与版本」查看条件和来源。点击选人推荐可浏览攻略，不会自动 BP；Ban 与阵容卡片的选中态只用于查看建议。
5. 按需打开「选人变化后自动分析」。默认关闭，仅在真实选人阶段触发；切换到其他页面时仍跟随本局阵容。大乱斗不展示 Ban 推荐。
6. 双方阵容全部锁定后重新「生成建议」，提示词会要求阵容倾向和简短点评；开启自动分析时沿用阵容变化触发。点评是基于已知阵容的教练估计。

源码新增「我的英雄池」折叠设置：全部英雄、仅常玩与想练、仅指定与想练。常玩结合本模式近期记录与非零熟练度；指定和想练每组最多 30 位，本机持久化保存，无需先配置 API Key。仅为本人推荐的 `picks` 受范围约束；Ban 位和队友补位保持按阵容分析。想练的英雄单独标注，不作为熟练依据。当前范围为空时不擅自放宽，提示调整设置。

分析同时提供近期同模式样本数、队列 ID、同分路场数和匿名英雄汇总；胜率只以已知胜负为分母，同分路胜率另列分母。样本未按补丁筛选，常规峡谷可能混合排位与匹配；全模式熟练度不能证明当前分路水平。少量个人胜率不作为下一局获胜概率。主进程会再过滤模型结果，保证列表间英雄不冲突；被过滤时直接显示原因提示。修改英雄池后取消旧分析并清空缓存建议。账号资料读取失败时保留公开阵容分析，明确提示缺少个人依据。

个人样本先排除重复、无效或时长缺失的对局；资料所属账号必须匹配本次开始分析的身份。正文中的明确选人或 Ban 指令若与过滤后候选冲突，会拒绝该条回复；正常保留已锁定队友不视为新增选人。概率规则会归一化加粗、全角等格式，并检查已覆盖的中英文与中文数字表达，仍不能代替全面语义核验。

大乱斗当前未读取本局可交换英雄池，`picks`、`bans`、`teamPicks` 均为空，只分析已知组合；海克斯还会明确提示未读取已选强化。阵容信息和资料缺口直接展示，其他来源与个人样本详情仍可折叠查看。

输出默认精简：普通摘要 32 字、最终阵容摘要 64 字、每条理由 28 字、阵容说明 56 字、版本影响 40 字，额外条件最多一条 24 字。这些是生成目标，摘要、卡片与阵容说明不互相复述，保留关键收益、代价及否定条件。模型超出摘要或阵容说明的展示长度时，可展开完整内容；主进程仍校验整段已解析文本，页面预览不改写分析结果。资料提醒合并为短提示，候选过滤、空英雄池和模式资料缺口优先显示，展开后可读全部原文。

## 数据与密钥

- LCU 提供本方预选/锁定、分路、队列 ID、队友、敌方可见英雄和已完成 Ban；不发送账号、玩家身份或会话标识。
- 源码新增的个人上下文只发送英雄 ID、个人近期场数/胜率、熟练度点数、推荐范围及想练列表；昵称、PUUID、召唤师/账号编号不会进入模型请求。教练页会说明这一数据范围。历史十人详情与时间线不整体发送给模型。
- 优先读取有效的当前客户端版本，独立记录 Data Dragon 与 OP.GG 统计版本。版本不匹配的统计与公告在请求模型前排除，缺少适用公告时强制清空 `patchImpact`，并移除不适用的来源标签。
- 英雄目录只提供名称与职业标签，不含逐技能、英雄克制或真实分路验证；OP.GG 数据为全球全段位排位分路汇总，不是玩家段位、指定对位胜率或匹配模式的实测强度。请求明确标注这一范围；自选英雄池中已有统计的英雄不因只截取热门前 30 位而遗漏。
- 版本公告按本次补丁查找 Riot 官方文章，不固定某个“最新版本”。Riot 新公告使用 26.x 等年份编号，Data Dragon 使用 16.x 等资源编号，分析保留两者。
- API Key 由 Electron `safeStorage` 加密后单独存入用户数据目录的 `ai-coach.json`；页面只读取密钥是否存在。系统加密不可用时拒绝保存密钥。
- 更换 Base URL 必须重新填写密钥，防止把原服务商密钥转发给其他地址。服务商错误正文不展示到页面或日志。
- 相同阵容和证据短时间复用分析；公告正文、统计内容、英雄目录或个人范围变化都会改变缓存键。选择、连接状态或客户端阶段变化时撤下不匹配的旧建议，重新生成失败时也不保留上一条作为当前结果。限流遵守服务端 `Retry-After`。

接口采用 OpenAI [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 的 `model`、`messages`、Bearer 认证和非流式回复。分析优先请求 `json_object` 输出；服务商明确拒绝该参数时仅回退一次，并记住其兼容性。模型须按提示词返回 JSON，主进程再验证字段与英雄 ID。
