本轮审查提示词及其实际输入、数据口径、选人阶段判断、输出过滤、缓存和展示。已修复可确定的程序问题。测试与页面验收使用合成回复，未向线上模型发送数据，未连接 Windows 客户端。

## 已修复的问题

| 优先级 | 原问题与影响 | 修复及证据 |
| --- | --- | --- |

| P1 | 锁定阶段、推荐范围和列表一致性主要依赖提示词 | 程序判断五人公开与五人锁定的区别，完整阵容停止选人、禁用与补位。本人、队友、Ban 三组候选不重复使用同一英雄；剔除建议会直接提示。 |
| P1 | 大乱斗没有可交换英雄池，却可能推荐任意目录英雄 | 未取得可交换池时关闭三组候选，只评已知组合；海克斯未取得已选强化时禁止约定格式的数值胜率，并直接说明缺口。 |

| P2 | 同模式总样本被误当同分路样本，未知胜负分母不清 | 提供队列范围、同分路样本、已知胜负场数与赢的场数，分别计算总体及同分路胜率；说明个人样本未按补丁筛选，熟练度是全模式累计。 |
| P2 | 英雄目录被标为技能依据，统计适用范围不明 | 来源改称「英雄目录（名称与职业）」，请求明确无逐技能/克制核验；统计明确为全球全段位排位汇总、非指定对位统计，比例单位为 0–1。 |
| P2 | 同一补丁的公告修订可能继续命中旧分析 | 缓存键包含完整公告、统计、个人上下文及目录内容；移除向模型发送的会话标识。重新生成先撤下旧回复，避免失败后继续展示旧结论。 |

## 仍需完成的内容质量验证

1. **可追溯的机制与克制资料。** 当前未接入逐技能及交互证据，模型机制判断仍依赖既有知识。提示词可以限制措辞，不能证明重做后机制、特殊交互和克制结论正确。应先补可定位版本、模式及来源的机制资料，再复核“针对谁＋机制收益＋主要代价”。
2. **真实模型场景评测。** 需要用匿名合成阵容实际运行目标模型，留存输入和输出，逐条核对盲选、明确对位、阵容取舍、分路合理性、Ban 优先级、预选变化、大乱斗和强化缺失。当前测试证明过滤规则能工作，不证明模型选角排序最优。
3. **概率校准。** 40–60 的粗粒度输出仍是主观阵容倾向，不能称为经过验证的预测准确率。没有历史对局与校准评测前，不扩大范围或声称提升获胜概率。当前自由文本规则覆盖约定与常见中文表达，不能替代全面语义验证。
4. **本局可用信息。** 当前没有大乱斗可交换池与已选强化，也没有常规峡谷的账号可用英雄清单、选人顺序或完整禁用阶段。程序不会据此执行 BP，建议点击只浏览攻略；这些资料未接入前不能承诺每个建议都可立即操作。
5. **Windows 实局联动。** 仍须在真实 LCU 中验证分路、队列、预选/锁定、不可见对手、跨账号和阵容变化全过程。已有模拟 IPC 与页面检查不能替代该验收。

这些项目是本轮明确记录的剩余边界，未标为已验证或已交付。
