# 局内战斗夸夸与嘲讽

0.2.0 接入。仅在 Windows 英雄联盟经典、极地大乱斗、海克斯大乱斗的加载/对局阶段工作。默认开启基础规则识别，可在偏好设置关闭总开关、分别关闭夸夸或调侃、调整音量。0.2.6 起取消固定播报间隔，旧配置中的间隔不再生效。云顶、斗魂、未知模式、大厅和赛后不触发。局内玩家必须匹配当前登录账号，身份不明确时保持安静。

## 事件与准确性

主进程按约一秒间隔串行读取本机 `https://127.0.0.1:2999/liveclientdata/allgamedata`，使用击杀、助攻、多杀、团灭、本人血量和生死状态。请求有超时和大小上限，自签名证书例外只作用于该固定 loopback 地址。

经典模式包括人机对局。事件参与者优先匹配玩家账号别名；事件返回英雄名时，只允许唯一英雄匹配，并兼容没有 Riot ID 的机器人。当前登录账号与局内本人仍只通过玩家身份核对，不能用英雄名替代；镜像英雄重名时不猜测。进入同一局的加载/对局阶段时，客户端暂时缺少模式元数据可沿用已确认的本局模式；返回大厅、新对局或明确的其他模式不沿用旧值。

| 类型 | 依据 |
| --- | --- |
| 残血险胜 | 本人近期击杀后存活，事件附近采样血量不超过 20% |
| 连续多杀 | 本人的 `Multikill` 事件，不能拿其他玩家的多杀触发 |
| 团灭大胜 | 己方 `Ace` 且本人十秒内实际参与击杀或助攻 |
| 队友配合 | 本人击杀有队友助攻，或本人助攻队友的击杀 |
| 漂亮击杀 | 本人击杀且没有更高优先级事件 |
| 连续阵亡 | 三分钟内至少两次阵亡，两次之间没有本人击杀或助攻 |

事件合并等待约两秒，优先团灭、多杀、残血击杀和配合。完全依据新战斗事件触发，没有总播报冷却或调侃冷却；播放与分析中不叠加请求、不积压旧台词，没有新事件时保持安静。基础模式六类事件各有十句原创台词，共六十句，避免连续重复。残血击杀后又阵亡会撤销尚未播报的存活夸奖。首次加入、重连、时间回退或数据断层重新建立基线，不补播旧事件。

这些是可观测事件的保守判断。没有技能命中、走位轨迹、敌方即时血量或可靠空间位置，不能识别空大、神级走位、救人意图，也不把其他路同时发生的击杀拼成一场团战。

## OpenAI 智能识别

「语音」页可切换基础规则或 OpenAI。连接统一在「设置 → OpenAI」配置，地址、模型、密钥与教练共用；在「语音提示词」独立编辑风格，再用底栏「保存配置」。使用 Responses API 的结构化输出，并设置 `store: false`；第三方服务的数据处理规则以该服务为准。

基础规则先确认事件，再把匿名化的近期击杀/助攻顺序、双方关系、自身血量/生死及支持的类别交给 AI。不会发送召唤师名称、Riot ID、LCU token 或账号编号。AI 可以选择类别、生成短句或判断证据不足而不播；本地检查类别、置信度、文本长度及专属台词匹配。AI 不能绕过开关、过期或玩家生死校验。服务商限流期间仍回退本地规则。

API 请求最多等待四秒，异常、鉴权失败、限流、未配置 Key 或不兼容响应回退基础规则。低置信度或明确跳过则保持安静。尊重 `Retry-After`，取消请求不会补播迟到结果；新对局、断连、关闭开关或更改设置时取消旧分析。

Key 使用 Electron `safeStorage` 加密后写入共用的 `ai-coach.json`，旧语音配置首次启动时迁移；渲染进程只知道是否配置，不读取已保存的密钥。更换服务地址必须重新填写密钥；移除共用密钥会同时影响教练与语音。智能识别按服务商规则计费，仅对触发候选事件请求，不逐秒调用模型。

## 专属台词与语音

每种事件支持五句专属台词，每句最多六十字；留空恢复默认。同一类别的专属台词在基础模式直接轮换，在 AI 模式要求原样选择，未采用时回退本地台词。LOL 专属提示词用于风格偏好，不能扩展数据里没有的事实。

现有内置台词保留游戏梗与高光播报。AI 新台词的默认方向改为朋友开麦的日常短口语：普通击杀顺口夸一句，配合兼顾助攻，残血带一点松口气的惊喜，多杀和团灭才提高兴奋程度。嘲讽保留直接补刀和笑点，减少赛事解说口号、排比、连续感叹号与刻意撒娇。事件依据仍然保持准确，不把普通击杀说成单杀、反杀、五杀、翻盘或整局胜利；玩家已保存的自定义风格偏好继续保留。

播报人设提供经典搭子、暴躁老哥、愤青少年、软萌甜妹、台湾软妹，**夸夸和调侃共用所选人设**。每个人设都有完整的五十句夸夸及十句调侃音频，共三百段。前四个人设共用夸夸文本，各自采用不同声线；台湾软妹另有五十句台湾口语夸夸和十句专用调侃，全部人设合计一百五十句原创文本。五十句调侃改用更直接的反问和游戏包袱，不再每句都温柔劝说或补一句下波加油。五种声线使用已确认的合成试听作为参考，老哥直爽带劲、少年年轻好胜、甜妹清甜亲近；台湾软妹夸夸与嘲讽统一沿用已选嘲讽的轻巧声线，保留两段已确认试听原音。AI 生成的夸夸和调侃也接收所选人设，默认优先 12–24 字，非专属台词超过 36 字回退简短基础台词；自定义的事件专属台词仍优先，原有六十字上限继续保留。

| 场景/风格 | 台词示例 |
| --- | --- |
| 残血险胜 | 残血收人头！阎王点名，你喊等会儿！ |
| 团灭大胜 | 团灭！对面集体黑屏，这波直接炸场！ |
| 经典搭子 | 不是哥们！你搁这给泉水刷日活呢？ |
| 暴躁老哥 | 血条一亮就灭！你搁这玩声控灯呢！ |
| 愤青少年 | 燃起来了！哦不，血条烧没了！ |
| 软萌甜妹 | 奶凶的是我，怎么先躺的是你呀！ |
| 台湾软妹夸夸 | 欸，这波打得漂亮耶，真的有帅到。 |
| 台湾软妹调侃 | 又黑屏喔？你跟泉水的感情，比跟我还好欸。 |

默认台词使用开发侧 VoxCPM2 预生成的情绪音频，压缩为 48 kHz 单声道、96 kbps MP3，随软件安装。当前音频大小可由 `npm run voices:check` 核对，整个语音包保持小于 20 MiB。客户端只带音频与播放代码，不包含模型、Python、参考 WAV 或推理环境；播放时不联网，也不需要安装中文语音包或填写语音 API Key。台湾软妹音频文件以 `taiwan-` 开头；口音和软嗲程度以实际试听为准。

正式音频保留模型原速、换气和句中停顿，只统一响度，不裁剪静音或加速。开发检查排除每秒低于 3.2 字、高于 8.5 字或超过七秒的异常片段，异常时换随机种子重新合成。字数只统计汉字、英文字母和数字，是筛查指标，不代替真人感和情绪判断。

编码参数位于 `scripts/combat-voice-delivery.json`，模型固定版本、20 步扩散参数及已确认参考哈希位于 `scripts/combat-voice-release.json`。五种合成参考和两段已确认原音保存在 `scripts/combat-voice-references/`，只用于开发复现；其余原始 WAV 保留在忽略提交的开发输出缓存。每次从无损源编码，避免 MP3 重复转码。资源清单记录实际合成指令、参考与源文件哈希、随机种子、原始时长、1 倍原速及最终字速。已确认原音保留其实际生成来源，不将后续参考或指令倒填成原始来源。所有处理在打包前完成，播放端不增加处理负担或依赖。

自定义和 AI 新台词、或内置资源缺失时，使用 Windows 中文 `System.Speech` 离线合成并缓存，缺少中文引擎会提示安装。该兜底会按人设选择可用的中文男声/女声并调整语速；台湾软妹优先匹配已安装的 `zh-TW` 中文声音，同一地区优先选女声，没有时回退其他可用中文声音。声音表现受系统引擎限制，不能获得与预生成音频相同的情绪效果。

默认播报音量为 65%，可在设置中调整至 0–100%。内置音频由 Windows MCI 播放，音量仅作用于本次播放，不修改系统或游戏音量，也不按音量重复生成文件。系统兜底的老哥、少年使用语速档位 3，其他角色使用档位 2；台湾软妹不再用档位 0 的慢速。系统兜底音量编码进 WAV，缓存按语速、角色及音量区分，避免语速改了仍播放旧缓存，最多保留一百五十条。升级时，无音量迁移标记且仍为旧默认 35% 的配置会提升到 65%；静音与其他音量值继续保留。新版保存配置时记录迁移标记，之后主动调回 35% 也会保留。

中文台词、音频路径与缓存路径通过 stdin 传入固定 PowerShell 脚本，不作为可执行命令拼接。停止、静音、切换人设或离开对局会取消正在查找/播放的音频，旧请求不能在取消后重新开始播报。

采集、分析与声音均由主进程管理，助手隐藏到后台后仍工作。关闭、静音、退出或离开对局会取消请求和语音进程，不保留待播队列。设置页提供夸夸和调侃试听。

## 验证范围

单元验证覆盖去重、连杀合并、击杀后阵亡、配合、连续阵亡、账号匹配、人机英雄名事件及无 Riot ID 的机器人、同局模式元数据缺失、其他模式、重连、关闭时在途请求、AI 回退及专属台词校验。实际 Windows 中文语音、国服 Live Client Data 和游戏中后台声音仍需 Windows 实局验收。

`npm run build` 会先检查所有人设的默认台词是否有对应音频、文件和参考 SHA-256 与大小是否一致、是否保留原速和原始时长，以及整个音频包是否小于 20 MiB；资源缺失、成品超过七秒或语速异常会阻止构建。`npm run voices:check -- --decode` 额外使用 ffmpeg 解码每段音频。Windows 测试会以零音量验证内置 MP3 的系统解码及中文路径；非 Windows 环境跳过该原生测试。

Apple Silicon 开发侧使用 `uv run --python 3.12 --with mlx-audio==0.6.3 python scripts/generate-combat-voices.py --prune` 续生成完整音频，需要 ffmpeg（含 libmp3lame）和已安装的项目开发依赖。默认采用 Apache 2.0 的 `mlx-community/VoxCPM2-8bit`，固定模型 revision，模型下载到开发机缓存。可加 `--limit 5` 先制作五个人设样本，`--styles taiwan` 仅制作台湾软妹，`--kinds rough` 仅制作嘲讽，或用 `--ffmpeg /path/to/ffmpeg` 选择编码器；`--local-model` 必须指向固定 revision 的本地快照。脚本读取正式台词目录，用同人设参考逐段合成，按参数指纹和成品哈希续用已完成条目；`--seed-offset` 用于重做异常录音。`--prune` 只在完整新目录已生成后删除退役 MP3，避免旧台词继续占包体。音频制作工具不随安装包分发。

可用 `uv run --python 3.12 --with mlx-audio==0.6.3 --with pypinyin python scripts/verify-combat-voice-content.py` 静音识别音频并筛查漏读或含糊发音，结果按文件哈希缓存于开发输出目录。这是辅助内容检查，情绪和实际听感仍需人工试听。

### 日常聊天声线试制

`scripts/combat-voice-natural.json` 单独定义五个角色的简短声音描述及夸夸、嘲讽小样。每次生成只要求一种情绪，不在同一条录音中切换夸夸和嘲讽。保留模型原速、换气和句中停顿，只归一化响度，不压缩句中静音、不做变调或加速。

使用 `uv run --python 3.12 --with mlx-audio==0.6.3 python scripts/audition-combat-voices.py --backend qwen` 生成 Qwen VoiceDesign 对照组；`--backend voxcpm` 使用 Apache 2.0 的 VoxCPM2 8-bit 开发模型，原生输出 48 kHz，20 步扩散推理。两个后端读取相同台词和人设要求；Qwen 对照采用模型默认的 0.9 temperature。VoxCPM2 的嘲讽生成引用同角色的合成夸夸原始音频，并记录参考文件哈希，以减少独立声音设计造成的声线变化。参数、随机种子、原始采样率及哈希记录在各自的 `manifest.json`，结果保存在 `output/voice-optimization/natural-v2/`。开发侧模型不进入安装包。

用 `uv run --python 3.12 --with mlx-audio==0.6.3 --with pypinyin python scripts/check-combat-auditions.py output/voice-optimization/natural-v2/voxcpm` 做解码和内容筛查，生成每个角色先夸后嘲的试听合集。每段台词独立合成，合集中的 0.6 秒间隔是试听分隔，不是模型句中停顿。小样不会自动替换正式三百段音频；内容识别通过不代表已经通过真人感、口音或角色一致性的听感验收。

女声进一步试制可用 `scripts/audition-combat-voices.py --backend voxcpm --styles sweet taiwan --variant A --output output/voice-optimization/female-v3/A`；B 版对应改为 `--variant B` 和 B 输出目录。两版保留相同夸夸和嘲讽台词，分别比较清甜轻快/柔软亲近、日常台妹/甜软台妹的声音方向。每版先制作一段完整聊天参考，再将同一参考用于该角色的夸夸与嘲讽；台湾参考文本使用台湾日常口语。`scripts/check-combat-auditions.py` 加 `--styles sweet taiwan` 检查局部试制，连同参考录音检查解码、内容和哈希。候选版本保存在各自目录，不覆盖前一轮试听。

后续 C 版针对“台湾 A 年龄感偏大、B 方向更接近，柔软版仍不足”的反馈，沿 B 的甜软方向重新设计年轻参考声线：甜妹目标为十九岁成年女生的清亮女中高音，台湾角色目标为二十岁成年女生的甜软、轻巧口语。减少温暖女中音、气声等容易混淆目标的描述，两个角色继续使用原来的夸夸/嘲讽台词作对照。用 `--variant C --output output/voice-optimization/female-v4` 制作，声音年龄和自然感仍以试听为准，不把提示词中的年龄当成已验证属性。

用户认可 C 版台湾试听的后半段后，D 版保留该嘲讽录音，以其原始 WAV 直接作为新夸夸的参考。D 版夸夸只要求沿用已选声线、口音和相近音量，不重新设计年龄或音色；`praiseReferenceKind: taunt` 指定参考来源。`--kinds praise` 可只重做前半段，结果放在 `output/voice-optimization/taiwan-v5/`，清单记录已选嘲讽的源目录与 SHA-256。继续生成该目录时保留已有参考、嘲讽音频和清单，避免重新制作已认可的后半段。详细内容筛查保存为 `verification.json`，交付摘要另用 `delivery-summary.json`，避免在大小写不敏感的文件系统上覆盖检查记录。

2026-10-27 使用用户指定的第三方服务及其 `gpt-5.6-sol` 模型做真实 Responses 验证：残血击杀、队友配合、连续阵亡三个样本均正确分类并原样选用专属台词，诊断响应耗时约 13.5、4.9、11.8 秒。诊断临时放宽超时；实际四秒期限下已验证回退。此结果说明接口与结构兼容，不代表该服务能稳定满足实时播报延迟。测试密钥没有写入源码、配置或验证产物。
