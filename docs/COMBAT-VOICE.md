# 局内战斗夸夸与嘲讽

0.2.0 接入。仅在 Windows 英雄联盟经典、极地大乱斗、海克斯大乱斗的加载/对局阶段工作。默认开启基础规则识别，可在偏好设置关闭总开关、分别关闭夸夸或调侃、调整音量。0.2.6 起取消固定播报间隔，旧配置中的间隔不再生效。云顶、斗魂、未知模式、大厅和赛后不触发。局内玩家必须匹配当前登录账号，身份不明确时保持安静。

## 事件与准确性

主进程按约一秒间隔串行读取本机 `https://127.0.0.1:2999/liveclientdata/allgamedata`，使用击杀、助攻、多杀、团灭、本人血量和生死状态。请求有超时和大小上限，自签名证书例外只作用于该固定 loopback 地址。

经典模式包括人机对局。事件参与者优先匹配玩家账号别名；事件返回英雄名时，只允许唯一英雄匹配，并兼容没有 Riot ID 的机器人。当前登录账号与局内本人仍只通过玩家身份核对，不能用英雄名替代；镜像英雄重名时不猜测。进入同一局的加载/对局阶段时，客户端暂时缺少模式元数据可沿用已确认的本局模式；返回大厅、新对局或明确的其他模式不沿用旧值。

| 类型 | 依据 |
| --- | --- |
| 残血险胜 | 本人近期击杀后存活，事件附近采样血量不超过 20% |
| 连续多杀 | 本人的 `Multikill` 事件，不能拿其他玩家的多杀触发 |
| 团灭大胜 | 己方 `Ace` 且本人十秒内实际参与击杀或助攻 |
| 队友配合 | 本人击杀有队友助攻，或本人助攻队友的击杀 |
| 漂亮击杀 | 本人击杀且没有更高优先级事件 |
| 连续阵亡 | 三分钟内至少两次阵亡，两次之间没有本人击杀或助攻 |

事件合并等待约两秒，优先团灭、多杀、残血击杀和配合。完全依据新战斗事件触发，没有总播报冷却或调侃冷却；播放与分析中不叠加请求、不积压旧台词，没有新事件时保持安静。基础模式六类事件各有十句原创台词，共六十句，避免连续重复。残血击杀后又阵亡会撤销尚未播报的存活夸奖。首次加入、重连、时间回退或数据断层重新建立基线，不补播旧事件。

这些是可观测事件的保守判断。没有技能命中、走位轨迹、敌方即时血量或可靠空间位置，不能识别空大、神级走位、救人意图，也不把其他路同时发生的击杀拼成一场团战。

## OpenAI 智能识别

「语音」页可切换基础规则或 OpenAI。连接统一在「设置 → OpenAI」配置，地址、模型、密钥与教练共用；在「语音提示词」独立编辑风格，再用底栏「保存配置」。使用 Responses API 的结构化输出，并设置 `store: false`；第三方服务的数据处理规则以该服务为准。

基础规则先确认事件，再把匿名化的近期击杀/助攻顺序、双方关系、自身血量/生死及支持的类别交给 AI。不会发送召唤师名称、Riot ID、LCU token 或账号编号。AI 可以选择类别、生成短句或判断证据不足而不播；本地检查类别、置信度、文本长度及专属台词匹配。AI 不能绕过开关、过期或玩家生死校验。服务商限流期间仍回退本地规则。

API 请求最多等待四秒，异常、鉴权失败、限流、未配置 Key 或不兼容响应回退基础规则。低置信度或明确跳过则保持安静。尊重 `Retry-After`，取消请求不会补播迟到结果；新对局、断连、关闭开关或更改设置时取消旧分析。

Key 使用 Electron `safeStorage` 加密后写入共用的 `ai-coach.json`，旧语音配置首次启动时迁移；渲染进程只知道是否配置，不读取已保存的密钥。更换服务地址必须重新填写密钥；移除共用密钥会同时影响教练与语音。智能识别按服务商规则计费，仅对触发候选事件请求，不逐秒调用模型。

## 专属台词与语音

每种事件支持五句专属台词，每句最多六十字；留空恢复默认。同一类别的专属台词在基础模式直接轮换，在 AI 模式要求原样选择，未采用时回退本地台词。LOL 专属提示词用于风格偏好，不能扩展数据里没有的事实。

默认台词与 AI 提示词采用热血开黑搭子加赛事解说的表达：普通击杀利落叫好，配合强调助攻与队友贡献，残血突出心跳感，多杀和团灭逐级推高气氛；用 LOL 语境中的梗、短句和比喻增强趣味与爆发力。夸张的是情绪，事件依据仍然保持准确，不把普通击杀说成单杀、反杀、五杀、翻盘或整局胜利。

播报人设提供经典搭子、暴躁老哥、愤青少年、软萌甜妹、台湾软妹，**夸夸和调侃共用所选人设**。每个人设都有完整的五十句夸夸及十句调侃音频，共三百段。经典搭子和前三种人设共用夸夸文本，各自采用不同音色与情绪；台湾软妹另有五十句台湾口语夸夸和十句专用调侃，全部人设合计一百五十句原创文本。老哥夸夸豪爽叫好、调侃嘴硬催战；少年夸夸热血欢呼、调侃中二不服输；甜妹夸夸元气甜夸、调侃俏皮奶凶；台湾软妹使用 Serena 女声，按台湾国语、轻柔软嗲、有自然气声和笑意的指令合成，夸夸温柔撒娇、调侃软声碎念。AI 生成的夸夸和调侃也接收所选人设，自定义的事件专属台词仍优先。

| 场景/风格 | 台词示例 |
| --- | --- |
| 残血险胜 | 残血收人头！阎王点名，你喊等会儿！ |
| 团灭大胜 | 团灭！对面集体黑屏，这波直接炸场！ |
| 暴躁老哥 | 兄弟！泉水是补给站，没让你在那买房！ |
| 愤青少年 | 这局还没完！倒下能复活，气势不能下线！ |
| 软萌甜妹 | 奶凶模式启动！先把小命保住，下波再凶回去！ |
| 台湾软妹夸夸 | 欸，人头拿到了耶，你这波好厉害喔。 |
| 台湾软妹调侃 | 欸，泉水都要帮你留位子了啦，下波陪我活久一点嘛。 |

默认台词使用开发侧 Qwen3-TTS-12Hz-1.7B-CustomVoice 预生成的情绪音频，压缩为 24 kHz 单声道、64 kbps MP3，随软件安装。当前音频大小可由 `npm run voices:check` 核对，整个语音包保持小于 20 MiB。客户端只带音频与播放代码，不包含模型、Python 或推理环境；播放时不联网，也不需要安装中文语音包或填写语音 API Key。台湾软妹音频文件以 `taiwan-` 开头；口音和软嗲程度以实际试听为准。

自定义和 AI 新台词、或内置资源缺失时，使用 Windows 中文 `System.Speech` 离线合成并缓存，缺少中文引擎会提示安装。该兜底会按人设选择可用的中文男声/女声并调整语速；台湾软妹优先匹配已安装的 `zh-TW` 中文声音，同一地区优先选女声，没有时回退其他可用中文声音。声音表现受系统引擎限制，不能获得与预生成音频相同的情绪效果。

默认播报音量为 65%，可在设置中调整至 0–100%。内置音频由 Windows MCI 播放，音量仅作用于本次播放，不修改系统或游戏音量，也不按音量重复生成文件。系统兜底音量编码进 WAV，缓存按音量区分，最多保留一百五十条。升级时，无音量迁移标记且仍为旧默认 35% 的配置会提升到 65%；静音与其他音量值继续保留。新版保存配置时记录迁移标记，之后主动调回 35% 也会保留。

中文台词、音频路径与缓存路径通过 stdin 传入固定 PowerShell 脚本，不作为可执行命令拼接。停止、静音、切换人设或离开对局会取消正在查找/播放的音频，旧请求不能在取消后重新开始播报。

采集、分析与声音均由主进程管理，助手隐藏到后台后仍工作。关闭、静音、退出或离开对局会取消请求和语音进程，不保留待播队列。设置页提供夸夸和调侃试听。

## 验证范围

单元验证覆盖去重、连杀合并、击杀后阵亡、配合、连续阵亡、账号匹配、人机英雄名事件及无 Riot ID 的机器人、同局模式元数据缺失、其他模式、重连、关闭时在途请求、AI 回退及专属台词校验。实际 Windows 中文语音、国服 Live Client Data 和游戏中后台声音仍需 Windows 实局验收。

`npm run build` 会先检查所有人设的默认台词是否有对应音频、文件 SHA-256 与大小是否一致，以及整个音频包是否小于 20 MiB；资源缺失会阻止构建。`npm run voices:check -- --decode` 额外使用 ffmpeg 解码每段音频。Windows 测试会以零音量验证内置 MP3 的系统解码及中文路径；非 Windows 环境跳过该原生测试。

开发侧可运行 `npm run voices:generate` 续生成音频，需要 Python 3、ffmpeg（含 libmp3lame）、ffprobe 和已安装的项目开发依赖。可用 `-- --limit 5` 先制作五个人设样本，`-- --styles taiwan` 仅制作台湾软妹，或用 `-- --ffmpeg /path/to/ffmpeg` 选择编码器。脚本读取正式台词目录，逐段调用官方公开演示并保存来源、音色、指令和校验信息；遇到额度/限流即停止，不绕过服务限制。音频制作工具不随安装包分发。

在 Apple Silicon 开发机上，也可使用 `uv run --python 3.12 --with mlx-audio==0.6.3 python scripts/generate-combat-voices.py --backend mlx` 本地制作，默认采用 Apache 2.0 的 `mlx-community/Qwen3-TTS-12Hz-1.7B-CustomVoice-4bit`。模型下载到开发机缓存，不放入项目资源目录。已验证的成品与原始音频可以续用，只有缺失、台词/指令变化或校验失败的条目需要重做；清单记录每段实际采用的后端和模型来源。

可用 `uv run --python 3.12 --with mlx-audio==0.6.3 --with pypinyin python scripts/verify-combat-voice-content.py` 静音识别音频并筛查漏读或含糊发音，结果按文件哈希缓存于开发输出目录。这是辅助内容检查，情绪和实际听感仍需人工试听。

2026-10-27 使用用户指定的第三方服务及其 `gpt-5.6-sol` 模型做真实 Responses 验证：残血击杀、队友配合、连续阵亡三个样本均正确分类并原样选用专属台词，诊断响应耗时约 13.5、4.9、11.8 秒。诊断临时放宽超时；实际四秒期限下已验证回退。此结果说明接口与结构兼容，不代表该服务能稳定满足实时播报延迟。测试密钥没有写入源码、配置或验证产物。
